Quickstart

Running in three steps

Configure your keys

Copy the example env file and fill in only the providers you'll use. Everything boots with zero keys set — unconfigured providers simply report unhealthy.

# from the repo root
cp .env.example .env
# edit .env: OPENROUTER_API_KEY, GROQ_API_KEY, … (only what you need)

Start the gateway

One process on 127.0.0.1:8787. No separate services — OpenCode Zen is reached directly over HTTPS.

uvicorn gateway.main:app --env-file .env --port 8787
# or, idempotently:  ./scripts/ensure-gateway.sh

Point Claude Code at it

Set one environment variable, then open the picker and choose any gateway engine.

export ANTHROPIC_BASE_URL="http://127.0.0.1:8787"
# in Claude Code:  /model

How it works

Replace one hop, keep one interface

Claude Code normally sends every request to Anthropic. Omnirouter replaces that single hop with a local translator: it accepts an Anthropic request, rewrites it into whatever the chosen provider speaks — OpenAI, Gemini, or Anthropic itself — streams the answer back, and translates the reply (tool calls and all) into the shape Claude Code expects.

Claude Code
/model picker
Omnirouter
match · translate · stream
Provider API
Groq · Gemini · …
Anthropic inOpenAI / Gemini out

Every hop is bidirectional — the reply streams back the same way. On the return, tool_calls become Anthropic tool_use blocks and inline <think> reasoning is stripped.

Features

What the gateway handles for you

translate

Protocol bridging

Anthropic ⇄ OpenAI and ⇄ Gemini, both directions, including system prompts and stop sequences.

tool_use

Tools everywhere

Your tool schemas are forwarded and the model's tool calls come back as Anthropic tool_use — on every OpenAI-compatible provider.

ping

Streaming keepalive

A heartbeat during long silences keeps slow models alive without ever cancelling the request.

<think>

Reasoning stripped

Inline chain-of-thought is filtered from the visible answer, even when a tag spans two chunks.

free=1

Free-tier tagging

Zero-cost engines are labelled in discovery so the picker makes the cheap choice obvious.

/health

Health & discovery

Per-backend health and a cached model list, so the picker only shows what can actually answer.

Daily use

Working with it

Subagents: free by default

The orchestrator spawns worker / reader subagents on a free engine unless you authorize a paid one. Choose per spawn by passing model: claude-groq-llama3, or pin all of them with CLAUDE_CODE_SUBAGENT_MODEL. Full policy in CLAUDE.md.

Give reasoning models room

max_tokens caps the total output — hidden thinking plus the visible reply. Set it too low and a reasoning model spends the whole budget thinking and returns nothing. The gateway adds no limit of its own; it forwards exactly what you send.

Troubleshooting

When something looks off

Empty reply from a reasoning model stop: max_tokens

It spent the whole token budget thinking. Raise max_tokens — reasoning models (Groq gpt-oss/qwen3, Gemini 2.5/3.x, OpenCode Zen) need headroom for hidden thinking plus the answer.

A model returns a rate-limit 429

Free tiers share upstream pools, so a given model may be limited one minute and fine the next. It's surfaced as a clean error, never a silent blank. Retry, switch to another free engine, or set a personal key for that provider.

Provider unhealthy or auth error no key

That provider's key isn't set. Cerebras and NIM stay inert until CEREBRAS_API_KEY / NIM_BASE_URL+NIM_API_KEY are present. Add the key and restart the gateway.

Security

Keys never leave the machine

Real keys live only in .env, which is gitignored and never tracked. .env.example holds placeholders only. No key appears in any tracked file or any commit, across the whole history. The gateway binds to 127.0.0.1 and sends each key only to that provider's own API over TLS — never to a third party.
